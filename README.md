# خدمات جيرود — PWA

تطبيق عربي RTL مبني بـ HTML وCSS وJavaScript دون إطار عمل أو مكتبات خارجية. البيانات تُقرأ من Google Sheets المنشور للقراءة، وتُخزّن آخر نسخة ناجحة محلياً. التطبيق يستخدم Service Worker لتخزين ملفات الواجهة الأساسية.

## الحالة بوضوح

هذه حزمة تنفيذية كاملة كبنية أولى قابلة للنشر بعد إعداد المصدر، لكنها **ليست مُعتمدة إنتاجياً بعد**: لم يُربط بملف Google Sheet حقيقي، ولم يُنشر على GitHub Pages، ولم يُختبر على أجهزة فعلية أو على Google Apps Script منشور. لا تضع معلومات مياه أو مناوبات أو طوارئ قبل التحقق الميداني منها.

## إعداد Google Sheets

1. أنشئ Google Spreadsheet.
2. أنشئ التبويبات بالأسماء الدقيقة الموجودة في مجلد `sheets-template`، ثم انسخ محتوى كل CSV إلى التبويب المناسب.
3. في تبويب `Settings`، حدّث القيم التي تبدأ بـ `SETUP_`. لا تترك أمثلة غير حقيقية فعالة.
4. في كل تبويب، الصف الأول هو عناوين الأعمدة. حافظ على أسماء الأعمدة.
5. من Google Sheets اختر **ملف → مشاركة → نشر على الويب**، وانشر المصنف أو التبويبات المطلوبة بصيغة CSV. اجعل الملف للقراءة العامة فقط إذا كان المحتوى عاماً؛ لا تضع أرقاماً خاصة أو معلومات حساسة.
6. انسخ Spreadsheet ID من عنوان الملف إلى `SHEET_ID` في `data.js`.
7. تأكد أن رابط gviz لكل تبويب يُرجع CSV في نافذة خاصة قبل نشر التطبيق.

### ملاحظة CORS

قراءة Google Visualization CSV مباشرة عبر `fetch` قد تختلف حسب إعدادات النشر والمتصفح. إذا منع المتصفح الطلب، لا يوجد تجاوز آمن من الواجهة الثابتة. استخدم Apps Script كواجهة بيانات عامة تُرجع JSON مع ترويسات CORS مناسبة، أو استضافة وسيطة موثوقة. لا تستخدم JSONP أو إدخال بيانات الشيت عبر `innerHTML`.

## إعداد الإحصائيات عبر Apps Script

1. افتح ملف Google Sheets نفسه، ثم **الإضافات → Apps Script**.
2. انسخ `gas/Code.gs` إلى محرر Apps Script.
3. من إعدادات المشروع → Script Properties أضف `SPREADSHEET_ID` بقيمة معرف الملف.
4. أنشئ تبويب `Stats` (أو اترك السكربت ينشئه) بأعمدة: `received_at, day, visitor_hash, event_kind`.
5. انشر كتطبيق ويب: Execute as **Me**، Who has access: **Anyone**. هذا يجعل endpoint قابلاً للإرسال العام؛ راقب الحصص والاستخدام.
6. انسخ رابط `/exec` وضعه في قيمة `stats_endpoint` ضمن Settings.

لا توجد هوية شخصية. المعرف المحلي قابل للمسح أو التغيير، ويمكن أن يتكرر عبر الأجهزة أو يتغير بعد حذف بيانات المتصفح. التكرار يُمنع تقريبياً لكل معرف/يوم. endpoint العام قابل للإساءة، لذا الإحصائيات تقديرية وليست تدقيقاً مالياً أو قياساً دقيقاً للزوار الفريدين.

## النشر على GitHub Pages

1. أنشئ مستودع GitHub وارفع جميع الملفات مع الحفاظ على المجلدات.
2. من Settings → Pages اختر النشر من الفرع الرئيسي ومجلد `/root`.
3. انتظر رابط HTTPS. لا يعمل Service Worker على `file://`؛ يحتاج HTTPS أو localhost.
4. افتح الرابط على الهاتف، ثم تحقق من البيانات وميزة التثبيت.
5. بعد تغيير `data.js` أو `sw.js`، ارفع الملفات. عند تغيير ملفات الواجهة غيّر `CACHE_VERSION` في `sw.js` لإجبار تحديث الـ cache.

## إدارة المحتوى

- `Settings`: إعدادات التطبيق والألوان والنصوص وواتساب والإعدادات الزمنية.
- `Water`: الحي، موعد المياه، الملاحظة، وقت التحديث.
- `Pharmacies`: معلومات المناوبة وتوقيتها وموقعها. يجب أن يكون التاريخ `yyyy-mm-dd` والوقت `HH:mm`.
- `Emergency`: الأرقام المعتمدة فقط.
- `Ads`: الموضع `home_banner` أو `inline_card` أو `footer`، وتواريخ صلاحية اختيارية.
- `Neighborhoods`: قائمة الأحياء الفعالة وترتيبها.

## حدود واحتياطات

- لا يمكن ضمان صحة البيانات الميدانية من الكود؛ عيّن مسؤولاً لتحديثها والتحقق منها.
- GitHub Pages لا يوفر خادماً أو أسراراً أو حماية API. لا تضع مفاتيح أو صلاحيات في ملفات الواجهة.
- PWA installation ليس متاحاً بنفس الطريقة في كل متصفح. على iOS قد يلزم التثبيت يدوياً من قائمة المشاركة.
- دعم SVG كأيقونة PWA متفاوت؛ لإنتاج أفضل توافق أضف PNG مقاس 192×192 و512×512 إلى manifest بعد تجهيزها.
- روابط الصور الخارجية تعتمد على توفر خادم الصورة؛ الصور الكسولة اختيارية وليست مطلوبة لتشغيل التطبيق.
- وقت سوريا يتغير بحسب قواعد المنطقة الزمنية. يعتمد الحساب على `Intl` و`Asia/Damascus` في المتصفح. اختبر أوقات التوقيت الصيفي عند تغيّر القواعد.
- لا تعرض أرقام طوارئ قبل تأكيدها محلياً.

## الاختبار

راجع `TEST-CHECKLIST.md` بعد ربط المصدر والنشر. اختبارات التشغيل المحلية التي لا تتطلب حساب Google لا تثبت نجاح النشر النهائي.
